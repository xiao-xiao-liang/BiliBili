# 视频社区设计讨论

## 已确认

- 产品定位：参考 B 站体验的独立视频社区，拥有自己的用户账号和视频内容。
- 项目目的：学习、作品展示，并通过实现理解视频平台的技术难点。
- 学习主线：实际实现上传 → 处理 → 发布 → 播放，覆盖断点续传、多清晰度处理、失败重试及播放时切换清晰度；使用成熟编码工具，不自行实现视频编码算法。
- 第一版功能：账号、视频投稿、视频列表与详情、播放、弹幕、基础评论和点赞。
- 后续范围：直播、私信、付费会员、创作者收益、个性化推荐算法。
- 交付形式：Web 端，后端使用 Go，前端使用 React + TypeScript + Vite + Tailwind CSS v4 + shadcn/ui（基于 Radix Primitives）；shadcn/ui 与 Radix 提供无障碍交互，Tailwind CSS 定义样式。
- 学习精力分配：前端做到完整、易用，主要精力投入 Go 后端与视频链路。
- 开发者基础：尚未学习 Go；有 Java 后端经验，了解数据库、Docker、Redis 和消息队列。
- 运行环境：第一阶段本地运行，使用小规模测试视频；线上演示另作后续里程碑。
- 预算约束：目前不购买服务器、视频存储和流量。
- 时间投入：工作日每天两小时，周末全天；尚未给出完成期限。
- 投稿单位：一次投稿目前只包含一个视频，包含必填标题、可选简介和自动截取的封面。
- 提交动作：上传前填写标题和简介，通过“上传并自动发布”按钮明确表达提交意图；第一版使用自动封面。
- 发布规则：全部目标清晰度处理成功后自动发布，观众即可观看；不采用作者手动发布流程。
- 访问权限：游客可以观看已发布视频；登录后才能投稿、评论、发送弹幕和点赞。同一账号可以观看和投稿，不需要单独申请创作者身份。未发布内容仅作者本人可见。
- 第一版不做独立管理员后台。
- 账号：用户名唯一且区分大小写，保留注册时的大小写；`Alice` 与 `alice` 可作为两个不同用户名，登录按大小写精确匹配。使用用户名和密码注册、登录、退出；密码使用安全哈希保存。第一版不接短信、邮件和第三方登录，不做自助找回密码。
- 页面范围：最新发布优先且支持分页的首页、视频详情页、投稿页、我的投稿、注册页、登录页。视觉采用原创极简黑白风格（MONO，支持亮/暗双主题），详见 [前端视觉与交互设计](specs/frontend-design.md)；搜索、排行榜、关注及个人主页留到后续。
- 内容修改：作者可修改标题和简介；暂不替换视频文件，需要更换视频时重新投稿。
- 删除投稿：作者可删除任何阶段的投稿，删除后停止对外提供内容，后台清理文件，不提供恢复功能。删除必须阻止未完成或重复执行的后台任务将投稿重新发布。
- 弹幕：记录文字及对应的视频时间位置，按播放进度回放；发送后本地立即显示，其他观众重新加载后可见。提供弹幕开关，仅支持普通滚动文字；实时推送留到后续。
- 评论：平铺展示、最新优先，不做回复和楼中楼；用户可删除自己的评论，作者可删除自己投稿下的评论。
- 点赞：对象是投稿，每位用户最多一次有效点赞，可取消；重复请求不重复计数。不做评论点赞、点踩或弹幕点赞。

## 已确认的技术边界

- 后端结构：模块化单体；账号、投稿、互动等模块位于同一个 Go 项目，耗时的视频处理由可独立启动的后台任务进程执行。
- HTTP 框架：Gin。
- 数据访问：pgx + sqlc，手写 SQL 并生成查询调用代码。
- 登录鉴权：使用用户指定的 [sa-token-go](https://github.com/sa-tokens/sa-token-go/blob/main/README_zh.md)及其 Gin 集成，Redis 保存 Token / Session 状态；通过 Compose 管理 Redis，配置持久化及数据卷。Redis 首期专注鉴权状态，业务数据继续保存于 PostgreSQL。
- Token 传递：浏览器使用 HttpOnly Cookie 携带 sa-token-go Token，应用负责 CSRF 防护；退出时撤销当前服务端 Token 并清除当前浏览器 Cookie。
- 登录生命周期：固定七天有效，到期重新登录，不随访问自动续期；允许多个浏览器同时登录且各自使用独立 Token，退出仅影响当前浏览器。第一版不做设备管理页面。
- 请求中间件：使用 slog 记录请求及后台任务，配备请求 ID、panic 恢复、统一错误响应、请求体大小限制及参数校验；普通 API 与媒体读取分别设置超时并支持取消；登录、注册和创建上传等操作采用单进程限流。配合已确认的鉴权、资源归属与 CSRF 防护，媒体接口保持流式读取。
- 输入范围：MP4 容器、H.264 视频、AAC 音频，允许无音轨；普通横屏，画面高度 360～1080 像素，单文件不超过 1 GB，时长不超过 30 分钟。不支持的文件给出明确提示。
- 输出清晰度：最高提供 360p、720p、1080p 三档；保持原始宽高比，仅生成不超过源视频高度的档位。例如 480p 只生成 360p，720p 生成 360p 和 720p；低于 360p 的输入拒绝。
- 局部失败：保留已成功生成的清晰度成果，仅重试失败的部分；全部目标清晰度成功前不发布。
- 上传恢复：保留已上传部分；重新打开页面并选择同一文件后可以继续上传。
- 处理恢复：后台重启后可重新执行未完成任务，允许当前未完成的一档从头处理。
- 重复执行：同一任务执行多次不产生重复投稿或重复发布。
- 失败反馈：作者可见状态和失败原因；可重试的处理错误最多自动重试三次，之后允许手动重试。
- 本地验收基线：一个文件上传、一个后台转码任务、两个浏览器会话观看视频可以同时进行。后台先逐个处理转码任务，记录处理耗时、CPU、内存和磁盘占用，再据此优化；尚未承诺具体吞吐量和处理时限。
- 业务存储：PostgreSQL 保存业务数据及任务状态；媒体使用本地 S3 兼容对象存储。用户接受 MinIO 或 RustFS；依据官方资料，整体核对稿默认选择 RustFS 1.0.6，实际可用性在 M0 本机验证。
- 后台调度：已选择 RabbitMQ，第一版用于视频转码和媒体清理任务，替代此前只依靠 PostgreSQL 任务表派发工作的方案。PostgreSQL 保存业务及任务状态；可靠投递、有限重试、幂等处理的实现建议见实施方案。
- 播放：FFmpeg 生成 HLS，前端使用 hls.js；支持播放、暂停、拖动进度、音量、全屏及手动切换清晰度。首期以本机桌面 Chrome 验收。
- 续传身份：通过文件内容哈希识别同一文件并校验分块；上传记录仅允许所属用户访问。
- 上传过期：未完成上传连续七天无活动后过期并清理；页面明确提示需要重新上传。
- 媒体保留：保留原视频、封面及所有成功生成的清晰度文件，直到作者删除投稿。
- 开发运行：通过 Docker Compose 管理 PostgreSQL、Redis、RabbitMQ 与对象存储；Go API、后台处理进程及 React 在本机运行，方便调试。若采用 MinIO，用户接受固定源码版本构建本地镜像。
- 上传路径（暂定）：浏览器直接分片上传到对象存储，Go 后端管理上传记录、鉴权、分片签名及完成确认；用户回答“暂时可以”，因此该路径需要早期技术验证，不能视为已经验证可用。
- 媒体访问：对象存储桶私有，浏览器通过 Go 媒体接口读取 HLS 清单及分片，每次请求检查投稿状态。删除后拒绝新的媒体请求，已传输或缓冲到浏览器的内容无法收回。
- 协作方式：按里程碑提供可运行代码、必要验证和关键设计讲解，结合开发者的 Java 经验解释 Go；按账号、上传续传、转码播放、互动、故障恢复验收逐步推进。

## 整体核对与验证项

- 产品范围、框架及基础服务、登录规则和请求中间件均已确认，用户已认可整体方案方向。用户进一步明确需要先完成 M0～M5 的架构、表结构、接口及验收设计，当前交付为 [详细技术规格](specs/README.md)，原工单拆分不作为执行计划。
- 直传保持暂定，M0 验证分片签名、CORS、恢复和校验之后依据结果确定；若需要改变上传路径，提供具体复现结果和取舍。
- RustFS 固定镜像、sa-token-go 模块组合、RabbitMQ 消息确认及四个基础服务的本机资源占用尚未实测，列为 M0 验证内容。

用户明确要求暂不开始 M0。当前只编写和评审技术规格；未安装依赖、启动基础服务、执行 DDL 或实现业务代码。此次设计文档直接保存在项目中，不以配置工单系统为前提。

## 外部依赖核实

- 2026-11-25 核实：[MinIO 官方社区仓库](https://github.com/minio/minio)显示于 2026-04-25 归档，README 明确不再维护、社区版仅提供源码。用户随后接受 MinIO 或 RustFS，因此整体核对稿采用 RustFS，MinIO 固定源码构建仅保留为备选路线。
- 当前根目录 [Dockerfile](https://github.com/minio/minio/blob/master/Dockerfile)仍依赖 `minio/minio:latest` 且复制预先构建的二进制，不能将该文件本身视为独立、已验证的源码构建流程。
- RustFS 提供 [1.0.6 正式发行](https://github.com/rustfs/rustfs/releases/tag/1.0.6)及 [Docker 部署说明](https://docs.rustfs.com/en/installation/container/docker)，官方镜像标签列出 ARM64 支持。[Go SDK 文档](https://docs.rustfs.com/en/developer/sdk/go)使用 AWS SDK for Go v2，支持配置独立 endpoint 与 path-style 访问。
- [RustFS S3 文档](https://docs.rustfs.com/en/administration/protocols/s3)列出常规 multipart、预签名及 CORS 能力，同时明确存在兼容边界；文档可能领先固定发行版。本项目尚未拉取镜像或执行浏览器上传验证。
