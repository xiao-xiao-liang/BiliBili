## 设计如何成为可检查的进度

- 每项验收使用稳定编号，例如 `M2-AC-04`。实现、验证记录和阶段汇报必须引用编号。
- 每次动手前列出本次覆盖的编号及表/API 增量；结束后列出已完成、未完成、验证证据和偏差。不能只汇报“完成 M2”。
- 执行记录使用 [进度与变更记录](progress.md)。当前所有条目均为“未开始”；静态文档检查不是功能验收通过。
- 修改字段、枚举、接口或阶段范围时，先更新共享契约和受影响的阶段 spec，再实现。涉及已确认产品规则的改变须明确说明取舍。
- 阶段验收通过也不自动授权进入下一阶段；用户当前授权的是详细设计。

## 契约的权威位置

数据库字段、类型和约束以 `schema.sql` 为结构定义，状态迁移与事务语义以 `data-model.md` 为准；HTTP 形状以 `api-contract.md` 为准。阶段文件引用共享定义，不另造同名字段。若发现冲突，先修正文档，不由实现者静默选择一种解释。

领域用语沿用 [GLOSSARY](../../GLOSSARY.md)。媒体访问与 MQ 选择遵循 [ADR-0002](../adr/0002-private-media-through-api.md) 和 [ADR-0003](../adr/0003-rabbitmq-background-jobs.md)。旧工单拆分不作为当前执行计划。

## 必须由 M0 得出实测结果的事项

| 编号 | 已定方向 | 仍待实测的事实 | 失败后的处理 |
| --- | --- | --- | --- |
| V-01 | RustFS 1.0.6、私有 S3 桶 | ARM64 镜像、分片签名、CORS、ETag、Range 和中止行为 | 记录复现；修正适配或评审改用用户允许的 MinIO |
| V-02 | 浏览器分片直传 | 断开/重开页面恢复和分片完整性流程 | 保留验证记录，评审是否改为 Go 转发分片 |
| V-03 | sa-token-go + Gin + Redis | 固定模块版本的编译、Cookie、多端退出、固定有效期 | 修正项目适配层；更换库需重新讨论 |
| V-04 | RabbitMQ + amqp091-go | 确认、不可路由返回、断线重投和消费超时配置 | 修正配置/适配，不宣称“恰好执行一次” |
| V-05 | 本机运行四个基础服务 | 镜像摘要、实际空载/工作负载资源 | 根据测量调整限额；不预先声称能达到特定吞吐量 |

这些是明确列出的验证条件，不是省略的设计工作。其余业务行为按本目录契约实现。
